# 评测数据集说明

目录里有两个数据文件和一个模板：

| 文件 | 用途 | 当前条数 |
|---|---|---|
| `golden_set.jsonl` | 金标集：正常问答用例，用于算 P / R / F1 | 22 条 |
| `negative_set.jsonl` | 反例集：不该召回 / 不该作答的用例 | 8 条 |
| `template.jsonl` | 空模板，新增用例时照抄格式 | 2 条示例 |

每行一个独立 JSON 对象（JSONL 格式），**不支持注释**，说明信息写在 `note` 字段里。

---

## 一、为什么金标集里没有 chunk_id

`chunk_id` 是 Milvus 自动生成的主键，**每次重新导入都会变**。
如果把 chunk_id 写死进金标集，跑第一次有效、跑第二次就全废了。

所以金标集改用**稳定定位符**——只描述"这条切片应该长什么样"，
由匹配器在运行时用真实切片的字段去比对。刷新重跑完全不受影响。

## 二、金标集字段

```jsonc
{
  "qid": "G001",                       // 用例编号，唯一
  "query": "《骆驼祥子》这本书主要讲的是什么？",
  "role": "listener",                  // listener / operator / editor
  "golden": [                          // 期望召回的切片定位符（可多个）
    { "source_file": "骆驼祥子", "keywords": ["祥子"] }
  ],
  "reference_answer": "《骆驼祥子》讲述北平洋车夫祥子……",
  "must_include":    ["祥子"],         // 答案里必须出现的关键词
  "must_not_include": [],              // 答案里禁止出现的关键词
  "note": "基础事实题"
}
```

### `golden[].定位符字段`

| 字段 | 含义 | 匹配方式 |
|---|---|---|
| `source_file` | 切片来自哪个文件 | `source_file_name` **包含**该串（不区分大小写） |
| `book_name` | 切片所属书名 | `book_name` **包含**该串 |
| `author_name` | 切片所属作者 | `author_name` **包含**该串 |
| `content_type` | 内容类型 | **精确相等**（七类白名单之一） |
| `entry_name` | 条目 / 章节名 | `entry_name` **包含**该串 |
| `keywords` | 正文必须出现的词 | `content + title` 中**全部命中**才算匹配 |
| `exclude_keywords` | 正文不能出现的词 | 命中**任一**即判不匹配 |

规则要点：

- 定位符里**所有非空字段必须同时满足**；字段留空或省略 = 不约束。
- 一个切片命中 `golden` 里**任意一个**定位符就算相关。
- 召回率按**被覆盖的定位符个数**算，而不是按切片条数算——
  防止"一条金标被召回 5 个相邻切片"把召回率刷满。

### 定位符设计建议

- **能用元数据就用元数据**。`source_file` / `book_name` 是 LLM 抽取后写进每个切片的，
  比正文关键词稳定得多。
- **keywords 选专有名词**。选"国清寺""那罗延""临春"这种全库唯一的词，
  命中即证明召回精准；选"的""了"这类高频词毫无区分度。
- **keywords 别贪多**。写 3 个词就要求 3 个词必须同时出现在同一条切片里，
  切片被切碎之后很容易一个都命不中，反而让召回率虚低。

## 三、反例集字段

```jsonc
{
  "qid": "N001",
  "query": "《济公传》第一回里，李修缘的父亲是谁？",
  "role": "listener",
  "expect_abstain": false,             // false=越界召回类, true=库外拒答类
  "forbidden": [                       // 不该被召回的切片
    { "source_file": "骆驼祥子" },
    { "source_file": "隋唐演义" }
  ],
  "note": "越界召回：问济公传，召回其它书都算污染"
}
```

### 两类反例

**1. 越界召回类（`expect_abstain: false`）**
问题明确指向某本书，却召回了别的书 → 记**误召回率**。
指标越低越好，理想是 0。

**2. 库外拒答类（`expect_abstain: true`）**
知识库里根本没有答案（天气、时效信息、库中不存在的书名）→
期望系统明确回答"没有找到"，记**拒答准确率**。
指标越高越好，理想是 1。

> `N006`（怎么用万用表测主板短路）是特意留的**源项目痕迹检查**：
> 那是源项目（设备说明书知识库）的典型问题，如果改造后还能答出来，说明领域清洗不彻底。

## 四、新增用例的流程

1. 把 `template.jsonl` 里的示例行复制一份，改 `qid`（不能重复）。
2. 先跑一遍系统，人工看召回的切片是不是你想要的那一批。
3. 用 `source_file` + `keywords` 把那批切片的特征描述出来。
4. 保存文件，**点界面的「刷新」再点「评估」**即可看到新用例的分数。

不需要改任何代码——runner 每次运行都会重新读取这两个文件。
